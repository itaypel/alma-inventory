# עלמא · מערכת ניהול מלאי

מערכת לניהול מחסן של אינסטלציה, מיזוג וחשמל:

- **עובדים** נכנסים עם שם משתמש וסיסמה ויכולים **רק לקחת** מהמלאי. כל לקיחה נרשמת על שמם, עם כמות (מארזים או יחידות) ופרויקט.
- **מנהל** רואה הכל: מוסיף ועורך מוצרים (תחום, מדף, מק״ט, מחיר, יחידה או מארז של 10/20/100), ממלא מלאי, רושם לקיחות על שם עובדים, מנהל משתמשים, ומוריד דוחות.
- **דוחות**: מלאי נוכחי, מלאי לפי תחום, ודו״ח שבועי – כ־Excel או PDF. כל יום חמישי ב־16:00 הדו״ח השבועי נשמר אוטומטית במערכת.

טכנולוגיות: Next.js (רץ על Vercel) + Supabase (מסד נתונים והתחברות).

---

## התקנה – פעם אחת, בערך 20 דקות

### 1. Supabase – מסד הנתונים

1. נכנסים ל־[supabase.com](https://supabase.com) → **New project**. בוחרים אזור קרוב (למשל Frankfurt) ושומרים את סיסמת מסד הנתונים.
2. **SQL Editor** → **New query** → מדביקים את כל התוכן של `supabase/schema.sql` → **Run**.
   - (אופציונלי) אותו דבר עם `supabase/seed-example.sql` כדי לקבל מוצרי דוגמה.
3. **Authentication → Sign In / Providers → Email**:
   - לכבות **Allow new users to sign up** (חשוב! כך רק המנהל יכול ליצור משתמשים).
   - לכבות **Confirm email**.
4. **Project Settings → API** – מעתיקים שלושה ערכים:
   - `Project URL`
   - `anon public` key
   - `service_role` key (סודי!)

### 2. הקוד ב־GitHub

```bash
git init
git add .
git commit -m "Alma inventory"
git branch -M main
git remote add origin https://github.com/<המשתמש-שלך>/alma-inventory.git
git push -u origin main
```

### 3. Vercel – האתר

1. [vercel.com](https://vercel.com) → **Add New → Project** → בוחרים את הריפו `alma-inventory`.
2. ב־**Environment Variables** מוסיפים:

   | שם | ערך |
   |---|---|
   | `NEXT_PUBLIC_SUPABASE_URL` | ה־Project URL |
   | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | ה־anon key |
   | `SUPABASE_SERVICE_ROLE_KEY` | ה־service_role key |
   | `CRON_SECRET` | מחרוזת אקראית ארוכה (למשל 40 תווים) |

3. **Deploy**. בסיום מקבלים כתובת כמו `alma-inventory.vercel.app`.

הדו״ח השבועי מוגדר ב־`vercel.json` ורץ אוטומטית – אין צורך בהגדרה נוספת.

### 4. יצירת המנהל הראשון

במחשב, בתיקיית הפרויקט:

```bash
npm install
cp .env.example .env.local      # וממלאים בו את אותם ערכים כמו ב-Vercel
node --env-file=.env.local scripts/create-manager.mjs admin "השם שלך" סיסמה-חזקה-כאן
```

עכשיו נכנסים לאתר עם `admin` והסיסמה. את שאר העובדים יוצרים מתוך המערכת: **לוח מנהל → עובדים → משתמש חדש**. המערכת מייצרת סיסמה זמנית ומציגה אותה פעם אחת – מוסרים אותה לעובד. סיסמה שנשכחה מאפסים מאותו מסך.

## שימוש יומיומי

| מי | מה |
|---|---|
| עובד | נכנס → בוחר אינסטלציה / מיזוג / חשמל (או מחפש לפי שם, מק״ט או מדף) → ״לקחתי״ → כמות + פרויקט |
| מנהל | ״הוספת מוצר״, ״לקיחת מוצר״, ״הפקת דו״ח״ במסך הבית; ״מילוי מלאי״ ו״עריכה״ בכל שורה בטבלה |
| מנהל | ״הורדת דוח מלאי עכשיו״ – Excel של כל מה שיש כרגע במחסן |
| מנהל | עובד שעזב → ״השבתה״ (ההיסטוריה שלו נשמרת, הוא לא יכול להיכנס) |
| מנהל | מוצר שלא מחזיקים יותר → ״עריכה״ → ״הסרה מהקטלוג״ (ההיסטוריה נשמרת) |

## איך זה בנוי (למי שימשיך לפתח)

- המלאי נשמר תמיד **ביחידות** (`stock_units`). מארז הוא רק דרך תצוגה ולקיחה – `pack_size`.
- **המחיר** (`price`) הוא למארז, או ליחידה כש־`pack_size = 1`. בכל תנועה נשמר שווי ליחידה באותו רגע, כך ששינוי מחיר לא משנה דוחות ישנים.
- **שינוי מלאי** אפשרי רק דרך הפונקציות `take_product` ו־`restock_product` במסד הנתונים, והן רושמות כל תנועה ביומן. אי אפשר לשנות כמות ישירות, גם לא מנהל. הרשאות ה־RLS נבדקו: עובד לא יכול למלא, להוסיף מוצרים, לרשום על שם אחר או לראות תנועות של אחרים.
- **הדו״ח השבועי**: `vercel.json` מפעיל את `/api/cron/weekly-report` ביום חמישי ב־14:00 UTC (16:00 בחורף בישראל, 17:00 בקיץ). השבוע מתחיל ביום ראשון 00:00 שעון ישראל. בתוכנית החינמית של Vercel ההפעלה יכולה לזוז עד שעה.
- שמות משתמש הופכים מאחורי הקלעים לכתובת `username@alma.local`, כי Supabase דורש אימייל. לא נשלחים מיילים.
